# 文档导入·分段全量预览与调整（Import Segment Editor）设计文档

- 日期：2026-09-10
- 状态：已实施（实施计划 docs/superpowers/plans/2026-09-11-import-segment-editor.md）
- 阶段：文档导入体验二期，接续 2026-09-06 总体设计与 2026-09-09 成书导出设计

## 1. 背景与目标

文档/整本书导入（EPUB/PDF/Word/TXT/MD/HTML）在预览步只能看到前 8 条抽样，且文本截断到 120 字符（`ImportPreviewService` 的 `SAMPLE_ROWS=8` / `SAMPLE_TEXT_MAX=120`）。默认分段一旦有误——该断的没断、不该断的断了、章节识别错——只能等落库后再搜索定位、逐条修改，成本很高。

本功能把「检查与修正」前移到确认导入之前：**全量分段可见、可编辑、确认即落库**。

**需求（用户已确认）：**

- 预览**所有**分段，全文显示不截断
- 编辑操作四类：合并相邻段、在指定位置拆分一段、编辑/删除段文字、调整章节归属（含章节改名）
- 定位手段：按章节分组导航、筛选可疑段（超长/超短，阈值可调）、顺序翻页；**不做关键词搜索**

**成功标准：**

- 一本几千段的书，导入前能翻完全部分段；发现切错的段当场合并/拆分/改字/改章节
- 每次编辑后，去重结论（新导入/跳过/覆盖）与统计即时更新，确认落库结果与预览所见一致
- 既有"一次预览一次确认"模型不变：确认成功即消费会话，失败/过期需重新上传

**范围外（本期明确不做）：** 对照表格导入的全量预览与编辑、关键词搜索、按段落重跑自动分段（换参数重切）、会话服务端持久化/断线恢复、拖拽调段序。

## 2. 关键决策记录

**架构：服务端可编辑会话（用户在三个候选中选定）。** 每个编辑操作即时调用一个小 API，直接修改服务端内存会话（`ImportPreviewStore`）中的分段，并立即重算受影响行的去重结论。落选方案：

- *前端本地编辑缓冲*（确认时一次性提交操作列表）：操作组合校验复杂、统计在前端过期、去重要到最后才重算，出错发现太晚
- *一次性下发全量到前端*：上限 10 万行时单次载荷几十 MB，浏览器内存压力大，或被迫加行数上限造成"大书不能编辑"的不一致

选服务端方案的理由：单一数据源、每次操作即时校验、翻页/筛选天然反映编辑结果、confirm 协议几乎不动；代价是多约 7 个小端点（人速操作，请求开销无感）。

**其他已确认决策：**

- 编辑无「保存」按钮：操作即生效，服务端会话始终是最终真相
- 合并拼接沿用 `TextSegmenter` 的拼接规则（CJK 直接拼接、拉丁词间补空格）
- 章节改名成已有章节名 = 两章合并（特性而非错误）
- 会话 TTL 保持 30 分钟，改为**滑动续期**：每次 rows 拉取或编辑操作都刷新，活跃编辑不会中途过期
- 删除全部段后允许停留在编辑器，但确认按钮在 0 段时禁用
- `sampleRows` 从预览 VO 中移除（前端不再使用）

## 3. 向导流程与前端设计

向导从 3 步变 4 步：

```
① 上传（textRole/文件/重复策略，不变）
② 统计与书目信息（统计卡 + 书目表单不变；删掉前 8 条抽样表，
   换成入口卡「全部分段 N 段 · M 章 → [预览并调整分段]」）
③ 调整分段（新增，全量预览 + 编辑，确认按钮在此步）
④ 结果（不变）
```

新组件 `frontend/src/components/SegmentEditorPanel.vue`（第③步主体），编辑状态全在服务端，组件只持有当前页 + 筛选条件，无需 Pinia。

**界面布局：**

```
┌ 调整分段 ─────────────────────────────────────────────────┐
│ [章节：全部 ▾]  [□ 只看可疑段  长段≥300 短段≤10]   当前 N 段（原 X 段）│
│ ┌──────────────────────────────────────────────────┐     │
│ │ ☑ #12 │ 学而时习之，不亦说乎？有朋自远方来…   [已编辑] │ ✏ 🧩 🗑 ⇆ │     │
│ │ ☐ #13 │ 本立而道生。                            [新导入] │ ✏ 🧩 🗑 ⇆ │     │
│ │ ☑ #14 │ …（全文显示，不截断）                     [跳过]   │ ✏ 🧩 🗑 ⇆ │     │
│ └──────────────────────────────────────────────────┘     │
│ [合并所选（3段）]                       分页 ← 1/48 → 每页100段 │
│ [← 上一步]                              [✓ 确认导入 N 段]    │
└────────────────────────────────────────────────────────┘
```

**交互细节：**

- **列表**：分页拉取（默认每页 100），每行显示全文、去重结论标签（新导入/跳过/覆盖）、「已编辑」标记；行操作图标 ✏ 编辑 / 🧩 拆分 / 🗑 删除 / ⇆ 并入上段
- **章节导航**：下拉列出各章及段数（含"未分章"），选中即过滤到该章；旁附"重命名"入口
- **可疑段筛选**：勾选后只显示 `len > 长段阈值`（默认 300）或 `len < 短段阈值`（默认 10）的段，阈值两个数字输入框可调
- **编辑文字**：弹窗 textarea 改全文，非空校验
- **拆分**：弹窗显示全文，光标落在哪就从哪切（实时预览上下两半）；拆出的两段沿用原章节
- **合并**：行尾 ⇆ 一键并入上一段；或勾选**连续**多段（不连续时按钮禁用）点「合并所选」；跨章节合并允许，结果取第一段的章节
- **改章节**：行操作弹窗，下拉选已有章节或输入新名（el-select allow-create）
- **章节改名**：作用于该章全部段
- 每次操作成功后刷新当前页 + 统计；校验失败 toast 后端消息
- **确认导入**仍只提交书目元数据（现有 `confirmImport` 协议不变）

## 4. API 设计

挂在现有 `ImportController`（`/api/v1/segments/import`），全部 `hasAnyRole('EDITOR','ADMIN')` + 会话属主校验（沿用 confirm 的检查），全部顺带滑动续期会话 TTL。写操作（PATCH/merge/split/DELETE/rename）的响应均携带 `stats: {totalRows, willImportRows, overwriteRows, skippedRows}`。

| 端点 | 请求 | 响应 |
|---|---|---|
| `GET /{previewId}/rows` | `?chapter=&suspicious=&longAbove=300&shortBelow=10&page=&size=` | `{stats, page, totalPages, rows: [{rowId, seq, prevRowId, chapter, text, planType, edited}]}`，text 为按 textRole 填充侧全文；stats 随每页返回供统计条即时显示 |
| `GET /{previewId}/chapters` | - | `[{title, rowCount}]`，title 空串代表"未分章" |
| `PATCH /{previewId}/rows/{rowId}` | `{text?, chapter?}` | `{row, stats}` |
| `POST /{previewId}/rows/merge` | `{rowIds: [...]}`（≥2 且当前顺序连续） | `{row, stats}` |
| `POST /{previewId}/rows/{rowId}/split` | `{atChar}`（0 < atChar < 文本长度） | `{rows: [上段, 下段], stats}` |
| `DELETE /{previewId}/rows/{rowId}` | - | `{stats}` |
| `POST /{previewId}/chapters/rename` | `{from, to}`（to 与已有章同名 = 合并） | `{stats}` |

- **rowId**：会话内稳定行 ID。建会话时按 1..N 分配，拆分新产生的段从 N+1 续编；前端以它为 key 与操作目标。`seq` 是当前顺序下的 1-based 位置，仅展示用
- **章节改名**：`from` 传空串即"未分章"改名——给所有无章节段统一冠章名，同样支持
- **错误码**：会话不存在/过期复用既有 `IMPORT_PREVIEW_NOT_FOUND`（404/3003），非本人复用 `IMPORT_PREVIEW_FORBIDDEN`（403/3004），与 confirm 行为一致；新增 `IMPORT_ROW_NOT_FOUND`（404/3006，rowId 不存在，如旧标签页操作）；参数校验失败 400 附消息
- **权限与范围**：仅 DOCUMENT 会话暴露编辑端点（TABLE 会话调用返回 400）

## 5. 服务端编辑与去重重算

**会话结构改造：** `ImportPreviewSession` 为 record，但持有 `List<ImportRowPlan>` 引用——编辑直接作用于该列表（ArrayList 原地增删改），新增可变伴随状态（下一 rowId 计数器）。`ImportRowPlan` 增加 `rowId` 与 `edited` 字段。`ImportPreviewService` 里现行的去重判定链（文件内 hash 去重 → 库内 hash 批查 → DOCUMENT 模式导入侧整字段查重）抽取为公共组件，预览构建与编辑重评共用同一套规则，避免逻辑漂移。

**新服务 `ImportPreviewEditService`**，职责：校验并执行七类操作、重算受影响行、返回统计。查询与重评所需的哈希比对/章节计数在每次操作时对会话行做一次 O(N) 内存扫描（10 万行毫秒级、人速操作无感知），不做常驻增量索引——避免会话伴随状态的生命周期管理，行为等价；库内查重仍只针对受影响行的 hash/文字做批查。

**重算规则（库内重查只触碰受影响行，不全量重跑）：**

| 操作 | 影响 |
|---|---|
| 改正文 / 合并 / 拆分 | 受影响行重算 `ContentHash`，按预览同款判定链重评 planType（文件内重复→跳过；库内重复→按重复策略跳过/覆盖/保留；否则新导入）。**含反向**：原本"跳过"的段改完不再重复 → 恢复"新导入" |
| 删除段 | 删除后，因与它同文而被标"跳过"（无库内 existingId）的段复活重评 |
| 改章节 / 章节改名 | 不碰 hash，仅影响章节归属与章节统计 |

`ImportExecutor` **不改**：确认时消费的就是会话里编辑后的最终 plans，编辑行的 hash 已是重算值，落库去重与预览展示一致；ES 同步流程不变。

**性能边界：** 上限仍为 `importProperties.maxRows()`（10 万）；rows 端点只取当页；每次编辑的库内查重走现有 hash 批量查询（仅受影响行的 hash）。

## 6. 异常与边界

- **会话过期**（离开超 30 分钟）：所有编辑端点返回 404（3003，与 confirm 同码）；前端弹窗"预览已过期，请重新上传"，向导重置回第①步。编辑内容随内存会话丢失——与现有一致性模型相同，不做持久化（见 §8）
- **跨标签页**：旧标签页持有过期 rowId → 404 → 提示刷新页面重取数据，不引入会话版本号
- **确认后防重放**：现有"取出即删除"语义保留，编辑端点同理只在确认前可用
- **0 段**：允许全部删空，确认按钮禁用
- **空文本/纯空白**：编辑与拆分校验拒绝（400），保证段落非空

# 部署器零基础用户 UI/流程重构设计

- 日期：2026-09-19
- 状态：设计中（用户授权全程推进至重构完成）
- 范围：`deployer/` 前端（Vue 3 + Element Plus）；Rust 后端命令与事件通道零改动

## 1. 目标与痛点

现有五步向导对零基础用户的核心障碍：

1. **环境检测页是"参数表"**：`el-descriptions` 罗列操作系统/内存/磁盘/网络/端口五项原始数据，用户必须自己判断哪些能过；下一步按钮不管检测结果都亮着，"检测"与"放行"脱节。
2. **Docker 一词无解释**：零基础用户不知道 Docker 是什么、为什么需要它、装它要多久。
3. **部署进度页只有原始阶段名**：`stage：message` 直接透出后端枚举名（pull/up），用户无法建立"我在哪、还剩多久"的心智。
4. **配置页密码规则靠提交失败才暴露**：字符限制、长度只在报错时可见，无实时指引。
5. **完成页信息平铺**：地址/账号/密码/按钮挤在一段文字里，"忘记密码只能清数据"这个关键约束只有一行副标题。
6. **管理窗口是运维视角**：容器卡片显示英文服务名与 state 原文（running/healthy），日志页空白等用户点按钮，卸载等危险操作与日常操作平铺同级。

## 2. 设计原则

- 每一步只问一个问题、只给一个主按钮
- 技术名词（Docker/容器/镜像/卷）要么不出现，要么跟一句白话解释
- 所有自动完成的事显示为"已为你完成"，而不是静默跳过
- 危险操作降级收纳，常规路径上不可见
- 状态用颜色和图标先于文字传达（绿=可用、黄=进行中、红=需要你处理）

## 3. 向导重构

### 3.1 步骤条

五步标题改为白话：`检查电脑` → `准备运行环境` → `设置密码` → `安装` → `完成`。保留 `el-steps simple` 布局，仅改文案。

### 3.2 检查电脑（StepEnvCheck）

- 每项检测一行：图标（✓/!/×）+ 白话标签 + 结论；通过项折叠为灰色小字摘要，只显示需要关注的问题项
- 端口被占用时直接给出"已为你换成 <推荐端口>"的采纳按钮（回填配置端口）
- 全部通过：大按钮「下一步」；有硬性失败（磁盘/网络）：按钮禁用 + 红色提示说明如何解决
- 内存不足仍允许继续（黄色提醒），与设计文档一致

### 3.3 准备运行环境（StepDocker）

- 首屏白话卡片："翻译数据库需要一个叫 Docker 的引擎来运行，本工具会自动为你下载安装，大约需要 3–10 分钟（视网速）。"
- 已就绪：绿色结果页「运行环境已就绪」+ 自动进入下一步（现有行为保留）
- 下载中：进度条 + 已下载体积（MB）+ 提示"请勿关闭电脑"
- 失败：白话错误 + 对应动作按钮（重试 / 一键安装 WSL2 / 打开设置指南），保留后端失败知识库原文的 pre-line 展示

### 3.4 设置密码（StepConfig）

- 标题与引导语聚焦唯一必答项：管理员密码；端口与高级选项收起为「更多设置」
- 密码实时校验：强度提示（位数达标 ✓、非法字符 ✓/×）随输入即时显示，不再只在提交时弹错误列表
- 确认密码失配即时红字提示；两者一致且合法时「开始安装」按钮才可用
- 默认端口若被环境检测推荐过备选端口，则用推荐值预填

### 3.5 安装中（StepDeploy）

- 把后端 stage 映射为三段白话子任务清单：下载组件（pull）→ 启动服务（up）→ 健康检查（wait 尾段），已完成打勾、当前项转圈
- 顶部保留整体不定进度条；当前子任务下方显示一行实时详情（message/pull 镜像名），技术细节降级为小字
- 失败时白话摘要 + 「重试」按钮，保留知识库建议

### 3.6 完成页（StepDone）

- 成功大图标 + 一句话结论；凭据做成结构化卡片：访问地址（链接样式）/ 账号 admin / 密码（明文+复制按钮），一行一项
- 醒目黄色警示框：忘记密码无法找回，只能清空数据重新安装
- 主按钮「打开网页」；次按钮「打开管理窗口」；密钥沿用与未设置提示保留现有语义

## 4. 管理窗口重构

### 4.1 状态页

- 顶部一条总状态横幅：绿「服务运行中，网页可正常访问」/ 黄「正在启动…」/ 红「Docker 未运行」
- 增加一个大的「打开翻译数据库」按钮（最高频动作前置）
- 容器卡片：中文角色名映射（网页服务/后台服务/数据库/搜索引擎）+ 英文小字原名；状态徽标中文化（运行中·健康 / 启动中 / 已停止 / 异常）
- 空容器列表文案改为引导语（尚未部署或已卸载）

### 4.2 日志页

- 保留按服务查看，服务下拉同样显示中文名；默认自动加载默认服务（backend）日志，不再空白等待
- 展示区加"最近 500 行"说明

### 4.3 设置页 / 维护页

- 设置页结构与行为不变（已有测试锚定），仅补引导文案
- 维护页：升级保留为常规项；卸载移入「危险操作」折叠区（红字标题），两步确认逻辑不变

## 5. 兼容与测试

- Rust 侧命令/事件/字段零改动；`ProgressEvent`、`PersistedState` 类型不动
- 现有测试锚点（`.admin-password`、`.submit`、`.copy-password`、`.tool-autostart`、`.port-input`、`.apply-port`、`.open-data`、`.upgrade`、`.uninstall`、`.view`、`button.submit` 等）全部保留
- 新增测试：环境检测通过/失败按钮状态、部署页子任务映射、完成页警示文案、状态页中文映射与横幅、日志页自动加载
- 验证：`npm test`（vitest）与 `npm run build:front`（vue-tsc + vite build）通过

## 6. 范围外

托盘、Rust 后端、CI、安装器、README 用户章节不在本次改动内（窗口尺寸 880×640/960×680 保持不变）。
